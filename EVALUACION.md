# Evaluación de la asignatura

La evaluación integra teoría, diseño electrónico, laboratorios, firmware, comunicaciones, Linux, proyecto ABP y sustentación individual.

## Estructura general

| Componente | Peso final |
|---|---:|
| Corte 1 – Arquitectura y placa base | 30% |
| Corte 2 – Firmware, drivers y comunicaciones | 30% |
| Corte 3 – Integración ESP32–Raspberry Pi 4 | 30% |
| Examen institucional | 10% |
| **Total** | **100%** |

## Corte 1

| Instrumento | Peso |
|---|---:|
| Quiz 1 | 2% |
| Preproyecto ABP 1 | 4% |
| Laboratorios y avances de PCB | 4% |
| Parcial 1 | 20% |
| **Total** | **30%** |

El Preproyecto 1 incluye requerimientos, arquitectura, sensores y actuadores, alimentación, protecciones, esquemático, PCB, DRC, Gerber, BOM y cotización.

## Corte 2

| Instrumento | Peso |
|---|---:|
| Quiz 2 | 2% |
| Preproyecto ABP 2 | 4% |
| Laboratorios de firmware y comunicaciones | 4% |
| Parcial 2 | 20% |
| **Total** | **30%** |

El Preproyecto 2 incluye firmware modular, driver propio, SPI, conectividad, HTTP o MQTT y arquitectura FreeRTOS con tareas, colas o sincronización.

## Corte 3

| Instrumento | Peso |
|---|---:|
| Quiz 3 | 2% |
| Laboratorios y avances de integración | 4% |
| Proyecto final ABP | 24% |
| **Total** | **30%** |

El proyecto final incluye integración física ESP32–Raspberry Pi 4, recepción y procesamiento, SQLite, dashboard, ejecución como servicio, logs, recuperación ante fallas, informe, video y sustentación.

## Trabajo grupal e individual

- Grupos de 3 estudiantes.
- Cada entrega identifica roles y aportes.
- Cada integrante debe conocer el sistema completo.
- La nota grupal puede ajustarse por dominio técnico, participación y sustentación individual.
- El código debe estar organizado y comentado; no se acepta una demostración que el grupo no pueda explicar.

## Publicación

GitHub contiene contenidos, fechas y criterios generales. Teams contiene tareas, enunciados controlados, rúbricas, entregas, retroalimentación y calificaciones.
